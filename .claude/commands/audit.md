# Audit (მხოლოდ შემოწმება)

არგუმენტები: $ARGUMENTS
- GitHub URL → ჯერ `git clone --depth 50 <url>` მიმდინარე საქაღალდეში და შემდეგი ნაბიჯები იქ
- რეჟიმი: GitHub URL-ით დაკლონილი რეპოზიტორია → **untrusted**, თუ `trusted` სიტყვა არ წერია. მიმდინარე (ჩემი) პროექტი → trusted.
  **untrusted** რეჟიმში **სამივე** აგენტს (`code-reviewer`, `security-auditor`, `tester`) გადაეცი: პროექტის სკრიპტები, ტესტები, build და dependency-ების ინსტალაცია **არ გაუშვა** — მხოლოდ კოდის წაკითხვა და სტატიკური ანალიზი. ამ საუბარშიც შენ თავად იგივე წესი დაიცავი.
- სხვა ტექსტი → სფერო (მაგ. `src/api`) ან რაზე გამახვილდეს ყურადღება

## ნაბიჯები
1. **კონტექსტი:** README, `PROJECT.md` (Accepted Risks-ის ჩათვლით), `PROGRESS.md`-ის Backlog, პროექტის `CLAUDE.md`, სტრუქტურა და stack. მოკლე შეჯამება გადაეცი სამივე აგენტს (ისინი ამ საუბარს ვერ ხედავენ): stack, მთავარი საქაღალდეები, სფერო, რეჟიმი.
2. **პარალელურად:** `code-reviewer`, `security-auditor`, `tester` (baseline: რა შემოწმებები არსებობს, შედეგები, ტესტების რაოდენობა).
3. **გადამოწმება:** reviewer-ების სიას ბრმად არ ენდო. თითოეული critical/should-fix ახლანდელ კოდში თავად გადაამოწმე; სიმძიმე შეადარე განსაზღვრებებს (ჩვეულებრივ გამოყენებაში არ ვლინდება → nit). დაუდასტურებელი → შესამოწმებელი, მიზეზით.
4. **`AUDIT.md`** პროექტის root-ში:
   - თავში: თარიღი, commit (`git rev-parse --short HEAD`), სფერო, რეჟიმი, baseline
   - დუბლიკატები გაერთიანებული (ერთი მიზეზი ან ერთი ადგილი → ერთი პუნქტი)
   - ID: A-001…; დალაგება: critical → should-fix → nit
   - თითოეული: ID, severity, file:line, სცენარი, შედეგი, გამოსწორება, owner (frontend-dev / backend-dev), status: open
   - ცალკე სექციები: „შესამოწმებელი (დაუდასტურებელი)" და „reviewer-ის მიგნებები, რომლებიც არ დადასტურდა — და რატომ"
   - Accepted Risks-ში ან Backlog-ში უკვე ჩაწერილი არ გაიმეორო
5. `AUDIT.md`-ის გარდა არცერთი ფაილი არ შეცვალო. commit მხოლოდ ამ ფაილის: `audit: <სფერო>`. push არასდროს.

## Report (ქართულად, მოკლედ)
baseline; რაოდენობა severity-ით; ყველაზე მნიშვნელოვანი პრობლემები (თითო წინადადება); რა ვერ შემოწმდა; შემდეგი ნაბიჯი: `/fix` (ყველა დადასტურებული critical + should-fix) ან `/fix A-00X ...`.
